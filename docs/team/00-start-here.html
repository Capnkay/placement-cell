1. What the app is

A college placement cell has to tell hundreds of students which company drives they can sit for, collect their applications, and move each one through shortlist, interview and offer. This app does that in one place. A student sees only the drives their own record qualifies them for, and when they do not qualify it says exactly why. The placement officer announces drives, tracks every candidate and reads live reports straight from the database.

It is a Jakarta EE 10 web application: Servlets and JSP on the front, EJB beans for the business rules, JPA with Hibernate and hand-written JDBC underneath, and MySQL 8 as the database.

2. Who exactly uses it

UserHow they get an accountWhat they can doTheir pages
Student Registers themselves at /register, or the officer imports them in bulk. Keep a profile and resume, browse drives, see eligibility with reasons, apply, withdraw, follow status and notes from the cell. /app/...
Placement officer (admin) Created by the college, never through the public form. Three exist in the demo data. Add companies, announce and close drives, move candidates through the pipeline, shortlist in batches, import students, read reports, browse the database, read the audit trail. /admin/...

What about the companies?

Recruiters do not log in. A company is a record the officer maintains, and the officer posts drives on its behalf, which is how a placement cell really works: the cell is the go-between. If the teacher asks "who puts up the job opportunities", the answer is the placement officer, from the Drives page.

4. Architecture in one picture

Read it left to right. A request meets the filters, then a servlet. The servlet asks an EJB (business rules and normal reads and writes through JPA) or the JDBC layer (reports and the database page). Both end at the same MySQL through the same server managed pool. The result goes back to a JSP, which produces the page.

5. Features at a glance

Student portal

  • Self registration with a real email domain check
  • Sign in with lockout after repeated failures
  • Profile: branch, CGPA, backlogs, phone, resume upload
  • Drives board that hides what you cannot apply for and says why
  • Apply, withdraw, and follow status with the cell's notes
  • Light and dark theme, remembered in a cookie

Officer portal

  • Companies and drives with eligibility rules per drive
  • Application pipeline and a batch shortlist
  • Bulk import of students
  • Reports read with plain JDBC, SQL shown beside the result
  • Database page: schema, rows, guarded SQL console
  • Audit trail, system page, and the Classroom JDBC page

9. Get it running on your laptop

  1. Clone the repository and open the folder placement-cell in VS Code.
  2. Start the MySQL 8 service. In MySQL Workbench, create the database and user once (the four lines are in README.md).
  3. In PowerShell, once per machine: .\setup.ps1 (downloads the server and JDK into server\).
  4. Every time: .\run.ps1. On the morning of the presentation use .\run.ps1 -Reseed so every drive has a fresh deadline.
  5. Open http://localhost:8080/placement/. Stop with .\stop.ps1.
  6. Shortcut: double click start.bat in the folder. It builds, starts the server, deploys and opens the browser.

The seeded dates are counted from the day the data is created. If the database was created days ago, drives can show "the last date to apply has passed". Run .\run.ps1 -Reseed to fix that.
